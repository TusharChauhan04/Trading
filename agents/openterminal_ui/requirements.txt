# OpenTerminalUI is imported, not installed. This file records what the
# modules we actually use need - so the next person can tell at a glance
# what is already satisfied and what a new module would cost.
#
# THERE IS NO agents/openterminal_ui/.venv, and that is deliberate. The
# upstream repo's own requirements.txt pulls FastAPI, SQLAlchemy, Redis,
# uvicorn and a web stack it needs to be an application. We borrow
# arithmetic from ~16 of its files; installing its world to do that would
# put the desk's pandas==2.3.3 pin at risk for no gain.
#
# HOW THE MODULES ARE LOADED: by file path via importlib, with the repo
# root on sys.path. See desk/robustness/scorecard.py for the pattern.

# --- already in the desk venv; the used modules need nothing more -------
# numpy          - robustness/scorecard (PSR, DSR, MinTRL), core/monte_carlo
# pandas==2.3.3  - services/indicators, scanner_engine/*
#
# Verified 2026-10-01: 16 of 20 target modules import and run on these two
# alone. scorecard.compute_robustness() needs numpy ONLY - no scipy, which
# matters because scipy is NOT in this venv (pandas' spearman corr fails
# here for that reason; rank-then-Pearson is the workaround).

# --- NOT installed. Each line is a module we are choosing to do without --
# PyYAML       -> backend/model_lab/montecarlo.py
#                 and needed to read backend/config/screeners.yaml as YAML.
#                 Light and wanted for Track A. Install when the screens
#                 are actually wired, not before.
# httpx        -> backend/adapters/yahoo.py, backend/nlp/filing_parser.py
#                 yahoo is not needed - the desk's own urllib intraday
#                 fetch already works and is throttled for NSE.
# SQLAlchemy   -> backend/core/factor_analysis.py
#                 The heaviest dependency and the one we miss least:
#                 vibe_trading's 206 India-ready factors already cover
#                 factor analysis, and they need no database.

# --- INSTALLED 2026-10-02, deliberately, to unblock core/statlab ----------
# statsmodels==0.15.0  (pulls scipy 1.18.1, patsy, formulaic, narwhals, wrapt,
#                       interface_meta - 7 packages)
#
# WHY: core/statlab/ is 10 modules of real statistics - regime_detection via a
# Markov switching model, cointegration_analysis, stationarity tests (ADF, KPSS,
# Hurst) - and every one of them imports statsmodels. Two of them bear on
# questions this project had closed: the regime gate (closed on a crude
# 50-day-mean proxy) and pairs_trading (parked on an in-sample hedge-ratio bug).
#
# VERIFIED BEFORE AND AFTER, because the pandas pin is load-bearing for every
# measurement in this project:
#   `pip install --dry-run statsmodels` first - pandas was NOT in the "would
#   install" list, so statsmodels accepts 2.3.3 rather than upgrading it.
#   After installing: pandas 2.3.3 HELD, numpy 2.5.3 unchanged, 1,241 desk
#   tests pass, this smoke test green, vibe_trading's factors still compute.
#
# ONE SIDE EFFECT CHECKED: scipy's arrival means pandas' spearman correlation
# now works where it previously raised. No desk module calls it - the
# rank-then-Pearson workaround written earlier lives in a scratchpad script,
# not in shipped code - so nothing silently changed behaviour.
#
# NOTE joblib==1.5.3 is a FREQTRADE constraint and applies to that agent's own
# venv. It is not installed in the desk venv at all, so it was never at risk
# here; an earlier version of this note implied otherwise.
